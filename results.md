How to read this:
- **AUC** says how well the model ranks customers. 0.5 is a coin flip, 1.0 is perfect.

## 2. Benchmarks: our models vs standard baselines

Every model in a table below sees the **same** 80/20 split (random seed 42), so the comparison is fair.

Models compared:
- **Majority class** (always predict the most common answer)
- **Logistic Regression** (with scaling)
- **Random Forest** (200 trees, depth 12)
- **LightGBM** (300 trees)
- **Our model**: Gradient Boosting (200 trees; depth 4 for churn, depth 3 for conversion) and Random Forest (150 trees, depth 8) for value

Extra columns:
- **AUC 95% CI**: a range from 200 bootstrap resamples of the test set. If two models' ranges overlap a lot, the difference is probably noise.
- **Lift @10%**: among the 10% of customers the model scores highest, how many times more often the event happens compared with the average customer. 3.0× means three times more.

### 2.3 Value (LTV) regression

The model predicts `log(1 + value)` because value is heavily skewed. R² is on that log scale. MAE (average error) is in the original currency.

| Dataset | Model | R² (log) | MAE |
|---|---|---|---|
| Synthetic | Mean predictor | 0.000 | 1,836 |
| Synthetic | Ridge | 0.410 | 1,468 |
| Synthetic | LightGBM | 0.626 | 1,168 |
| Synthetic | **Random Forest (ours)** | **0.609** | 1,187 |
| Retail (next-90-day spend) | Mean predictor | 0.000 | 694 |
| Retail | Ridge | 0.312 | 1,023 |
| Retail | LightGBM | 0.315 | 580 |
| Retail | **Random Forest (ours)** | **0.371** | **549** |

Notes:
- Synthetic top features: subscription type (60.9%), total spend (25.1%), engagement (5.6%).
- On Retail, 56.6% of customers spend nothing in the next 90 days, so the target is mostly zeros. That is why R² is modest. Our Random Forest still beats every baseline on both R² and MAE.
- Ridge has a worse MAE than the mean predictor on Retail. Its errors on the log scale get large when converted back to money.

What to know about the model's output:
- The text follows the segment numbers well. For example, the segment with 3.7% churn gets a "Savvy Senior Shopper" persona and the one with 44.5% churn gets "Seeking value amidst uncertainty".

## 4. How the data was checked and fixed

The first version of the synthetic data had problems. We found them by testing, then fixed them.

| Check | First version | After the fix |
|---|---|---|
| Churn rate | 55.4% (far above real businesses) | 18.1% |
| Conversion rate | 43.9% | 14.8% |
| Churn accuracy vs best possible | 64.5% vs about 65.1% (model was already at the ceiling) | AUC 0.840 |
| LTV R² | 0.9495 (the value was a formula of the input columns, so the model just learned the formula) | 0.609 |
| LTV correlation with total_spend | 0.76 | 0.34 |
| Silhouette (dashboard) | 0.092 | 0.078 |

What changed in the generator: customers now belong to 5 hidden types (champions, loyal regulars, bargain hunters, at risk, dormant). Churn and conversion rates are set to targets. Hidden noise is added so the best possible AUC stays below 1.0. LTV no longer comes straight from the spend columns.

Silhouette got slightly lower after the fix (0.092 to 0.078). The synthetic segments are still not well separated. See the notes below.

## 5. Things to know when reading these results

- **Our models are competitive** On every task our model is within about 0.01 AUC of the best baseline. The confidence ranges overlap. 
- **Synthetic scores mostly measure the generator.** The labels are drawn from rules we wrote, so a simple logistic regression does as well as a boosted model there (churn AUC 0.842 vs 0.840).
- **Online Retail churn is something we defined.** The dataset has no churn column. Churn here means "no purchase in the 90 days after a cutoff date". Features use only data before the cutoff.
- **Telco has 1,409 test customers.** Its AUC range is about ±0.02, so small differences between models there are not meaningful.
- **Silhouette on the dashboard vs benchmarks differ** because the dashboard uses the first 5,000 rows and the benchmark uses a random 10,000.
- **Personas are written by a small local model (`phi4-mini`)**, so names repeat and numbers are sometimes misread. They are not checked against the data automatically.
- **Segment names on the synthetic dataset are fixed labels.** On the other datasets they are built from each segment's value and churn (or subscription) rate.
