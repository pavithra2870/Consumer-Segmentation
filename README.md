# Consumer Intelligence Platform

An end-to-end, locally-hosted consumer analytics platform combining advanced ML segmentation, predictive modelling, LLM-powered persona generation, and a premium stakeholder dashboard.

The whole dashboard works on **four datasets** (one synthetic and three public ones). Pick a dataset from the dropdown at the top of the sidebar and every page shows that dataset. A **Benchmarks** page compares our models with standard baselines. Numbers and screenshots are in [results.md](results.md).

## Datasets

| Dataset id | Name | Source file in `data/` | Supports |
|------------|------|------------------------|----------|
| `synthetic` | Synthetic Consumers | `consumers.csv` (generated by the app) | churn, conversion, LTV, segmentation, fairness |
| `telco` | Telco Churn (IBM) | `WA_Fn-UseC_-Telco-Customer-Churn.csv` | churn, segmentation, fairness |
| `bank` | Bank Marketing (UCI #222) | `bank-full.csv` | conversion, segmentation, fairness |
| `retail` | Online Retail II (UCI #502) | `online_retail_II.xlsx` | churn, LTV (next 90 days), segmentation |

The three public files are not generated by the app. Place them in `data/` (the CSV files are git-ignored, and so is the Excel file). Licences: Bank Marketing and Online Retail II are CC BY 4.0. Check the Kaggle page for the Telco dataset before redistributing it.

**How each dataset is prepared**

- **Synthetic**: generated by the app. Customers belong to hidden types (champions, loyal regulars, bargain hunters, at risk, dormant). Churn is calibrated to about 18% and conversion to about 15%, with hidden noise so labels are not perfectly predictable. LTV is driven by a hidden value level, plan tier, tenure and retention, not by a formula of the spend columns.
- **Telco**: categorical columns are one-hot encoded. Blank `TotalCharges` (customers with zero tenure) are set to 0.
- **Bank Marketing**: the `duration` column (call length) is dropped because it is only known after the call ends, so it leaks the answer. `pdays = -1` becomes 0 plus a `previously_contacted` flag. Age is also grouped for the fairness audit.
- **Online Retail II**: the Excel file is read once and cached as `data/online_retail_II_transactions.csv`. Rows without a customer ID are dropped. Cancellations (invoices starting with "C") are treated as returns. The data is split by time: customer features use transactions before a cutoff date (last transaction minus 90 days). Churn means no purchase in the 90 days after the cutoff, and "value" is spend in those 90 days.

**What each page shows depends on the dataset.** A page only shows what the dataset supports. Online Retail has no age or gender, so the Fairness Audit link is hidden. Telco has no conversion model, so the Predictions page shows only churn.

## Setup Instructions

### 1. Install Ollama (optional but recommended)

Download from https://ollama.com and install.

Pull the model the project is set up to use (`phi4-mini`):
```bash
ollama pull phi4-mini
```

Verify it's running:
```bash
curl http://localhost:11434/api/tags
```

---

### 2. Backend Setup

```bash
cd backend

# Create virtual environment
python -m venv venv

# Activate (Windows)
venv\Scripts\activate

# Activate (macOS/Linux)
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Copy environment config
copy .env.example .env       # Windows
cp .env.example .env         # macOS/Linux
```

Edit `.env` if needed (default values work out of the box):
```ini
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=phi4-mini:latest
DATASET_SIZE=100000
N_CLUSTERS=6
```

Start the backend:
```bash
uvicorn main:app --reload --port 8000
```

API docs available at: http://localhost:8000/docs

---

### 3. Frontend Setup

```bash
cd frontend

npm install

npm run dev
```

Open: http://localhost:5173

## Running the Full Pipeline

Once both servers are running, open the dashboard and navigate to **Data Pipeline**:

Choose a dataset first with the **Dataset** dropdown in the sidebar.

**Public datasets (Telco, Bank, Retail)** have no generate step. Open **Data Pipeline** and click **Train Models**. The app builds the feature table from the file in `data/`, clusters the customers, and trains the models for the tasks that dataset supports. Each dataset keeps its own files, so training one does not change the others.

**Synthetic dataset**

**Step 1 — Generate Dataset**
- Click "Generate Dataset"
- Default: 100,000 rows (adjustable 10k–500k)
- Takes ~30–90 seconds depending on hardware
- Ollama generates review text if available; falls back to templates otherwise

**Step 2 — Train Models**
- Click "Train Models"
- Select number of clusters (default: 6) and method (KMeans or GMM)
- Runs: feature engineering → segmentation → churn/LTV/conversion models
- Takes ~2–5 minutes for 100k rows

After training completes, all dashboard sections become active for that dataset. A dataset that has not been trained yet shows "(not trained)" in the dropdown.

**Benchmarks**

Open **Benchmarks** to see how our models compare with the baselines on the selected dataset. Results are read from `models/benchmarks/<dataset>.json`. Click **Re-run** to recompute them (about 15 seconds for Telco, up to a few minutes for the synthetic dataset). You can also run them from the API (see below).

## ML Models

| Model | Algorithm | Target | Metric |
|-------|-----------|--------|--------|
| Segmentation | KMeans / GMM | Cluster assignment | Silhouette score |
| Churn | GradientBoostingClassifier (200 trees, depth 4) | is_churned | AUC, PR-AUC, accuracy |
| LTV | RandomForestRegressor (150 trees, depth 8) | log(ltv_actual) | R² (log scale) |
| Conversion | GradientBoostingClassifier (200 trees, depth 3) | converted | AUC, PR-AUC, accuracy |

Which models run depends on the dataset (see the Datasets table). Explainability uses SHAP TreeExplainer for all three models.

**Benchmark method.** Each benchmark task uses one stratified 80/20 split (seed 42) shared by every model. Classifiers are compared by AUC (with a bootstrap 95% range), PR-AUC, F1, accuracy and lift in the top 10%. Regression uses R² on the log scale and MAE. Segmentation uses silhouette, Davies-Bouldin and stability across seeds. Baselines are majority class, Logistic Regression, Random Forest and LightGBM.

**Fairness audit.** For each protected attribute the audit flags the highest-scoring share of customers (the same share as the dataset event rate) and compares flag rates between groups using the adverse impact ratio (80% rule) and a 10-point parity gap.

Feature engineering produces 25+ derived features including RFM scores,
engagement index, digital activity score, support burden, and session quality.

## Troubleshooting

**Backend won't start — "module not found"**
Make sure you activated the virtual environment (`venv\Scripts\activate` on Windows) before running uvicorn.

**SHAP import error**
SHAP has C++ build requirements. If installation fails:
```bash
pip install shap --no-build-isolation
```
The platform automatically falls back to permutation importance if SHAP is unavailable.

**Ollama shows "offline" in sidebar**
This is non-blocking. The platform works without Ollama using template-based personas and static review text. To fix, ensure Ollama is running (`ollama serve`) before starting the backend.

**Data generation hangs**
Check `GET /generate-data/status`. If status is "failed", check `backend/logs/app.log` for the error.

**Frontend shows blank/error after training**
Refresh the page. The frontend polls the backend every 3 seconds during training but a manual refresh after training completes is the most reliable way to load fresh data.

**Dropdown shows "(file missing)" for a dataset**
Place the dataset file listed in the Datasets table into the `data/` folder.

**Dropdown shows "(not trained)"**
Select that dataset, open **Data Pipeline**, and click **Train Models**.

**First Online Retail run is slow**
The Excel file is read once (it can take a minute or two) and cached as a CSV. Later runs use the cache.

**Virtual environment stops working after renaming the project folder**
A venv stores absolute paths. Delete it and recreate it (`python -m venv venv`, then `pip install -r backend/requirements.txt`).

**Windows path errors**
Ensure Python 3.11+ and Node 18+ are on PATH. Run `python --version` and `node --version` to verify.
